Resource Data Pack Loader
=========================

放进这个文件夹的任何内容，都会替换模组或 Minecraft 本身提供的内容。
它对每个世界生效，单人游戏和服务器皆然，
不需要任何开关。


不只是覆盖
----------

这里的资源包还可以用 JSON 文件定义新的方块、物品、生物群系乃至
整个维度，决定生成什么、在哪里生成，用钥匙或必须击杀的
生物给维度上锁，还能提前生成世界的陆地，让没人需要
等待区块加载。随模组一起发布的 HOWTO.md 涵盖了这一切。


如何添加文件
------------

打开模组的 jar，找到你想修改的文件，从“assets”开始复制它的路径。

要替换铁矿石的纹理，Minecraft jar 里的文件是：

    assets/minecraft/textures/blocks/iron_ore.png

那么你的版本放在这里：

    rdploader/assets/minecraft/textures/blocks/iron_ore.png

这就是全部规则。“assets”之后的路径始终与 jar 内的路径相同，
所以不需要重命名或移动任何东西。


保持整洁
--------

你也可以把文件归入一个命名的资源包，用 zip 打包：

    rdploader/MyTextures.zip        （zip 的顶层要直接是“assets”）

打包时，请选中里面的内容再压缩，不要压缩外面的文件夹。
如果 zip 的顶层是一个包着“assets”的单一文件夹，
它会被跳过，日志里会说明。

rdploader 里的文件夹不算资源包，会被跳过，日志里会说明。
零散文件请放在 assets 下，资源包请先压缩成 zip 再放进来。

同一个文件出现在两个地方时，命名的资源包优先于零散文件。
日志会写明每个文件来自哪个资源包，所以你总能看出哪一个胜出。


资源包优先级
------------

如果两个命名的资源包含有同一个文件，可以在 zip 名称前加上
RDPL 和一个数字来控制谁胜出。RDPL0 最先加载，数字越大
加载越晚，最后加载的资源包胜出：

    rdploader/RDPL0 BaseTextures.zip
    rdploader/RDPL1 SeasonalTextures.zip

大小写均可，数字后面的空格、短横线或下划线可有可无。
前缀在日志和 /rdpl list 里会被去掉，所以
RDPL1 SeasonalTextures 显示为 SeasonalTextures。


模组 API
--------

模组可以在自己的 jar 里携带 RDPL 内容，放在名为 rdploader 的
文件夹中，布局与资源包完全一致：

    thatmod.jar
      mcmod.info
      rdploader/assets/thatmod/blocks/ruby_ore.json

这些是默认值，不是覆盖。模组的资源包加载在这个文件夹里的所有
资源包之下，所以你放在这里的内容会胜出，而模组只能在它自己的
mcmod.info 里声明过的命名空间下提供文件。其他内容会被
忽略并给出警告，因此没有模组能悄悄重新定义别的模组或你的内容。

每个带有这种内容的模组，在第一次被发现时都会列入
config/mods.json：

    {
      "thatmod": {
        "enabled": true,
        "priority": -1
      }
    }

把 enabled 设为 false 即可关闭该模组的内容。priority 保持 -1 则
始终垫在最底层，也可以给一个数字，让它按上面的顺序与
编号资源包并列。日志里按从低到高列出资源包，模组自带的会有
标记，所以不会有你看不到的东西被加载。


玩家的资源包
------------

默认情况下，这里的文件位于玩家在选项界面选择的资源包之上，
所以资源包无法覆盖它们。这对整合包徽标之类的东西是对的，
对希望玩家能换皮肤的纹理则不对。

在 RDPL 前缀后加上 O 或 N，可以逐个资源包决定：

    rdploader/RDPLO Branding          始终胜出，资源包无法改动
    rdploader/RDPLN BaseTextures      资源包可以覆盖它
    rdploader/RDPL1O Seasonal         有优先级，并且始终胜出，两者兼备

没有字母的资源包遵循配置中的 overrideResourcePacks 选项，
/rdpl list 会标出会覆盖的那些。

没有前缀的资源包先于所有编号资源包加载，按字母顺序排列，
所以编号资源包始终胜过没有编号的。

想关闭某个资源包又不想删除它，在名称末尾加上 .disabled：

    rdploader/RDPL1 SeasonalTextures.zip.disabled

该资源包会被跳过，日志里会说明。去掉后缀即可重新启用。


你可以修改什么
--------------

纹理、模型、方块状态、语言文件、声音、字体、闪烁标语，以及模组在
assets 文件夹里存放的其他一切，比如指南书或手册。

进度和战利品表。它们属于服务端，所以在专用服务器上同样有效。

结构模板，即 assets/<modid>/structures 下的 .nbt 文件。保存在世界自己
structures 文件夹里的结构仍然优先于这里的文件，已经放置过的
结构在你离开世界之前保持加载。

配方，包括替换模组的配方或添加你自己的。配方只在游戏启动时加载，
所以这里的修改需要重启，而不是重新加载。

函数，即 assets/<modid>/functions 下的 .mcfunction 文件。Minecraft 只会
从世界自己的 data 文件夹读取它们，所以放在这里能让它们在每个世界
生效。保存在世界里的函数仍然优先于这里的文件。

注册表重命名，这样在模组重命名了某个方块之前保存的世界，会保留该方块
而不是丢失它。把文件放进 assets/<modid>/registry_remap：

    {
      "registry": "minecraft:items",
      "mapping": { "oldmod:old_name": "newmod:new_name" }
    }

注册表是该条目所属的那个，通常是 minecraft:items 或 minecraft:blocks。
重命名可以串联，把 A 映射到 B、之后又把 B 映射到 C，就会让 A 变成 C。

已经存在的事物的属性，无需改动它们的文件。assets/<yourpack>/overrides 里的
文件按路径指明目标，所以 overrides/minecraft/stone.json 修改的是
minecraft:stone，原版或模组方块皆可。方块可设置硬度、爆炸抗性、光照、
透光度、滑度、音效、采集工具与等级以及可燃性。物品可设置堆叠数量、
耐久和容器物品，任何物品都可以变成可食用，带有食物数值和效果。
药水的效果也可以重写。这些是即时生效的：禁用资源包并运行
/rdpl reload，每个数值都会弹回原样，无需重启。把所属模组的 id 写进
“requires”，这样该模组未安装时，文件会被悄悄跳过。

玩家战利品，游戏里根本没有对应名称的东西。玩家只会掉落自己的物品栏，
别无其他，所以 assets/<modid>/player_loot 里的文件会给他们一张
自己的战利品表：

    {
      "table": "mypack:entities/player",
      "mode": "add",
      "rollOnKeepInventory": false
    }

“add”在他们携带的一切之外，额外掉落这张表抽出的东西，“replace”则用它
取代物品栏掉落，rollOnKeepInventory 决定在保留物品栏的世界里
是否还要抽取这张表。

旗帜是个例外。一份定义会注册两个方块，你的和另一个名为 <name>_wall 的，
只有立着的那个有物品，放置时由它在两者之间选择。它的模型远远超出
自己所在的方块，立着时达到 16 中的 29.33，挂在墙上时则在方块下方
13，立着的方块状态需要 Forge 的格式才能以十六分之一为单位旋转。
指南里有完整的尺寸。

方块的掉落物可以是随机的，也不必是物品。它的 drops 列表里的条目各自
独立判定，除非你给它们权重，这样它们就共用一个池，恰好有一个会出现。
指明实体而不是方块的条目，会在方块原来的位置放出那个实体。

纹理可以用 JSON 写出来，而不必绘制。把文件按 PNG 命名并在末尾加上
.json，比如 textures/blocks/panel.png.json，再给它一个尺寸，如 16x16 或
16x32，一个“一个字符对应一种颜色”的调色板，以及由这些字符组成、
自上而下的若干行。另一个这样的文件可以扩展它，只写出想要不同的颜色，
所以同一种形状可以任意多次地换色，而不需要任何一张图片文件。它们绘制出的内容
保存在这里的 pixelmap-cache 中，每当某张图或它的模板改变时就会重新绘制。

也可以把东西拿掉。recipe_removals 里的文件按名称、命名空间或产物删除
配方，disabled 里的文件把方块和物品移出游戏而不注销它们，
所以世界保留原有的 id，删除该文件就能让一切恢复。战利品注入
会向已有的战利品表里加一个池，而不是替换它，block_drops 则为
不属于你的方块新增或替换掉落物。熔炉配方、燃料燃烧时间、矿物词典
名称、创造模式标签页和音效事件也各有自己的文件。

铁砧也可以学会新的活儿。anvils 里的文件指明一个物品、与它搭配放在
右槽的物品，以及铁砧在指定等级下提供的附魔或结果。取出成果
可以获得一项进度，物品也可以在获得这项进度之前一直无法使用。

hardness 文件为一组方块设定挖掘时间和爆炸抗性，exposures 文件
则定义辐射之类的危险：它作用于靠近指定方块、携带指定物品或
处于指定维度的玩家，分为若干等级，每级施加效果和伤害，
也可以从附近的生物和玩家身上染上，或随雨水降下。

CraftTweaker 和 GroovyScript 仍然和以前完全一样地工作。它们在本模组
之后运行，所以你的脚本移除或修改的内容会胜过这里的文件。

RDPL 适合替换一两个配方，而你自己内容的配方应当放在旁边的资源包里。
如果要在整个整合包范围内完全控制配方，CraftTweaker 和 GroovyScript 是
更好的选择。这里的文件会把原文件整个替换，所以要改一个材料或去掉
一个战利品条目，请用它们。


添加新内容
----------

资源包还可以添加自己的方块、物品和流体，用 JSON 描述。你
不需要编写或构建模组。

文件的路径就是它的名称。位于

    rdploader/MyPack/assets/mypack/blocks/copper_ore.json

的方块会注册为 mypack:copper_ore。没有需要填写或可能写错的名称字段。
如果某个真正的模组已经注册了该名称，模组胜出，你的文件会被跳过。

最简单的方块只要几行：

    {
      "type": "ore",
      "material": "rock",
      "harvestTool": "pickaxe",
      "variants": {
        "copper_ore": { "meta": 0, "hardness": 3.0, "harvestLevel": 1 }
      }
    }

模型、方块状态、纹理和语言条目仍按这个文件夹里其他文件的方式提供。

下面每一项都是 assets/<yourpack> 下的一个文件夹：

    blocks           items            fluids           materials
    worldgen         furnace          fuels            oredict
    sounds           tabs             recipes          recipe_removals
    loot_tables      loot_injections  advancements     functions
    structures       registry_remap   potions          potion_types
    brewing          villagers        trades           biomes
    villages         entities         gates            dimensions
    gamerules        worldtemplates   worldintro       pathintersects
    hardness         blastplaster     player_loot      overrides
    teams            scoring          caveregions      exposures
    structuremaps    citymaps         portalframes     block_drops
    texts            anvils           cards            disabled
    celestial        raids

方块有以下几种形态，由“type”字段决定：

    basic   ore     falling   slab    stairs   fence    door
    pane    wall    ladder    torch   crop     flower   cane
    log     leaves  sapling   vine    portal   trapdoor fence_gate
    banner  bell    container

物品有以下几种：

    basic   food    drink     potion  tool     armor    seed
    potion_bottle   rocket

药水类型总会出现在原版的药水、喷溅药水、滞留药水和光灵箭上，它们位于
酿造和战斗标签页。标签页是物品的属性，而不是药水类型的属性，所以
没有办法把它们挪到你自己的标签页里。potion_bottle 物品则是你自己的
容器：它和其他物品一样带有 creativeTab，在 potionTypes 里列出你指定的
药水类型，酿造台在任何玻璃瓶能用的地方都会接受它。

villagers/<name>.json 文件定义一种职业及其提供的生涯。trades/*.json 文件
为任何生涯添加交易，无论是你的还是 Minecraft 的，并指明职业、生涯和
交易出现的等级。如果指定的生涯不存在，日志会列出存在的那些。

entities/<name>.json 文件用已有的实体做出一个新实体。它指明所基于的
实体，以及不同之处：名称、皮肤、生命值和伤害、移动速度和跳跃高度、
绘制的大小、穿着什么、猎杀什么又无视什么，以及它是否仍遵守所基于
实体的生成规则。它是一个独立的实体，有自己的刷怪蛋和战利品表，
被它基于的那个实体不受影响。村庄地块可以被设定为安置它而不是村民。
它还可以带有自己的存储：物品槽、流体罐和能量缓冲，管道和线缆都能
接入，玩家潜行并右键点击它即可打开，Galacticraft 火箭也可以用同样的
方式变化，并由 rocket 类型的物品放置到发射台上。

villages/<name>.json 文件添加一个村庄可以建造的地块，可以是你描述的
农场，也可以是你的 .nbt 模板之一。同样的设置还能选择哪些原版建筑
仍会出现、村庄之间相隔多远，以及它们允许出现在哪些生物群系。

worldintro/<name>.json 文件在有人进入世界时、取得控制权之前，播放
一连串页面：图片上滚动的文字、标题卡、幻灯片，需要的话还有背景音乐。
文字是 assets/<yourpack>/texts 下的普通 .txt 文件。可以每位玩家播放
一次，也可以每次加入都播放。

teams/<name>.json 文件在游戏的计分板上设立一个阵营，生物、玩家或在
世界某个角落生成的任何东西到来时都会加入它，而 scoring/<name>.json
文件则是一个把击杀和死亡计给这些阵营的目标，按分数或时间结束一回合，
以聊天或卡片显示排名，并能为下一回合重置地图。

raids/<name>.json 文件在带着 omen 效果的玩家走进村庄时，向村庄派出
一波波敌人。Boss 栏显示还剩多少袭击者，村民会躲进屋里，袭击者会砸
开木门，一波敌人到来时村里的每口钟都会敲响。

cards/<name>.json 文件在发生某件事时（比如玩家进入某个生物群系）
在屏幕上显示一张卡片，同一文件夹里以本模组自带消息命名的文件，
可以改变那条消息的内容。


整个世界
--------

资源包不限于单个事物。dimensions/<name>.json 注册一个拥有自己的
地形、生物群系和天空的维度。gates/<name>.json 为抵达维度设定
条件，比如持有或消耗某个物品。portal 类型的方块会把走进去的人
送走，并记住是谁建造的。

世界模板还可以塑造主世界本身，设定海平面、岩浆海洋和地形噪声。
它只在创建世界时应用，之后不再应用，所以已经存在的世界保持原样。

worldtemplates/<name>.json 把一个世界的设置收进一个文件，
这样资源包可以一次性提供整个世界的形态，而不必要求
改十几处配置。它能设置的每一组，也都服从配置里的 control 类别，
由它决定是资源包说了算、配置说了算，还是这一组被彻底关闭、
任何资源包都无法开启。

维度还可以设定它头顶的外观和行为。它的雾、光照色调、太阳和月亮的
变暗、云层以及热浪都绘制在你自己的屏幕上，天气则决定是否下雨、
下雪或雷暴、阵雨持续多久，以及雨的颜色、粒子、声音和角度。

安装了 Galacticraft 时，celestial/<name>.json 会把资源包自己的星系、
行星、卫星、小行星带和空间站放到 Galacticraft 星图上，带有
galacticraft 块的维度则成为火箭可以飞往的地方。

worldgen 不只是矿石。一个条目是由一种分布放置的形状：团块、长矿脉、
板状矿体、晶洞、碗状地形、尖塔、结核、喷口、地表装饰、整棵树、
藤蔓、横跨多个区块的带状区域，或你自己的 .nbt 模板，可以均匀分布、
围绕某个高度、分形分布、沿地形、在洞穴地面或天花板上，或在水下。


biomes/<name>.json 文件定义生物群系：它的气候和颜色、构成它的方块、
装饰它的东西、在其中生成的生物，以及它在哪里生成。
它的编号由系统替你选定，并在每个世界第一次加载时写入该世界，
所以无论你之后再安装什么，它都保持不变。只有当某个生物群系必须
沿用别的东西已经用过的编号时才设置“id”，比如资源包取代一个
即将退役的模组。对世界里已经存在的生物群系重命名或删除，
会让它丢失，和给方块重新编号一样，所以重命名请改用 registry_remap。

村民显示的名称是语言键 entity.Villager.<career>，使用你所写的生涯名称，
一字不差。这个键空间由 Minecraft 和所有其他资源包共用，所以请把你的
命名空间放进生涯名称里，如 rdpltest.prospector。受影响的只有名称：
村民把生涯存成数字，所以重命名会改变现有村民的称呼，而调整生涯
列表的顺序会改变他们的生涯。

药水类型同样以文件命名，它显示的名称来自语言键
potion.effect.<namespace>.<name>，其他三种形态则用 splash_potion.effect.、
lingering_potion.effect. 和 tipped_arrow.effect.。


RUBIC 世界
----------

世界模板可以要求建造一个由立方体而不是 256 格方块柱构成的世界，
这样世界就向两个方向生长：远低于零的地板，远高于 255 的天花板，
整个范围里都有地形、洞穴和矿石。在其中游玩与平常无异。
你照样挖掘、建造、照明和旅行，而原版的生成窗口在更高的世界里
保持它惯常的形状，所以生成地形的模组仍然落在它们一直以来的位置。

资源包能从中得到的：由它自己决定的世界高度，在创建世界时设定一次；
原版窗口之下的深层世界，带有噪声洞穴、含水层，以及在你指定的
石头中的条带状矿脉；洞穴区域，即对洞穴生物群系的资源包版回答，
在整个地下以三维方式绘制，带有各自的地板、天花板、水位、生物和
结构；层叠在一起的维度，因此从一个世界的底部掉出去，会落进下一个
更深的世界，而从顶部爬出来则会回到上面；以及任何被省略的维度，
同一存档里仍保留它原本的世界。

在底层，世界以 16×16×16 的立方体存储，放在原版区域文件旁边的
自有区域文件里，独立地生成、加载和保存，并配有专为这种形状编写的
光照引擎。原版“世界高 256 格”的假设，在凡是承重的地方都已打上补丁，
从建造限制和虚空杀伤线，到寻路、传送门、信标、地图和渲染器。
其他模组的生成器看到的仍是一个看起来正常的 256 格窗口，
这就是它们的地形能正常工作的原因。

HOWTO.md 里有各项设置、世界可取的高度，以及这不能与之共存的模组。


关于 META 的警告
----------------

每个变种都有一个 meta 数字，世界文件存储的就是这个数字。
给人们世界里已有的变种重新编号，会把他们的方块变成别的东西。
新变种请加在末尾，永远不要给旧的重新编号。

一个方块有 16 个变种，因为四位元数据只能容纳这么多。
台阶有 8 个，因为一位用来表示在上还是在下，而楼梯、梯子、火把和
作物只有 1 个，因为朝向或生长阶段占用了其余的位。
物品没有这么紧，可以跳过一些数字。


这里为止
--------

这里描述的是事物是什么，而不是它随时间做什么。任何需要
方块实体、界面或每刻都运行的代码的东西，仍然需要真正的模组，
但有两个例外：container 类型的方块拥有带自己界面的物品栏，
实体变种可以带有存储。机器是够不到的；矿石、栅栏、食物
或流体则可以。


来自其他版本的资源包
--------------------

为本模组 1.20.1、1.21.1 或 26.x 版本制作的资源包在这里也能加载。
zip 会在自身内部被转换一次，写入 versions/1.12.2 文件夹，
现代版本的文件保持原样，所以同一个 zip 在每个版本上都能继续使用。


查看你的更改
------------

按 F3+T 重新加载纹理、模型、语言文件、进度和战利品表。在服务器上，
输入 /reload 也一样。配方是例外，如上所述：它们只在启动时加载，
所以修改配方需要重启。

如果你添加或删除了文件，请改用 /rdpl reload。编辑一个
原本就存在的文件，只需 F3+T。

/rdpl reload textures 只重新加载纹理，在大型资源包里比 F3+T 快得多。
models、languages、sounds 和 shaders 的用法相同。不写名称则重新扫描
文件夹并重新加载一切。

/rdpl list 显示加载的每个资源包及其内容。点击资源包即可查看。

/rdpl which minecraft:textures/blocks/stone.png 显示是哪个资源包
提供了该文件，以及它之下被遮盖的资源包。

/rdpl config unused 列出 rdploader/config 里不再被任何已安装
资源包定义的选项文件，/rdpl config prune 会删除它们。
/rdpl pixelmap 显示像素图最终的样子，/rdpl biome list 和 here
则告诉你生物群系的信息，/rdpl team 和 /rdpl round 用于资源包定义的
阵营和回合。

这些命令无需管理员权限，因为它们只读取你自己电脑上的文件。
在专用服务器上，/rdplserver reload 重新扫描服务器的副本。


出问题时
--------

先看日志。进度、战利品表、配方、函数和结构都会连同它们来自的资源包
一起记入日志，任何出错的地方都会记为警告并说明原因。

对于纹理和其他资源，/rdpl unused 列出你的资源包中尚未被任何东西
请求过的文件，这通常意味着路径有拼写错误。请在游戏加载完成后运行，
并注意有些文件只在需要时才会加载，比如你所用语言之外的其他语言。

大小写很重要。如果你的文件是 Stone.png 而游戏请求的是
stone.png，它仍会加载，但警告会让你重命名。请务必重命名，
因为在这个模组之外，这个文件根本找不到。
语言文件最容易出错：它们是 en_us.lang，不是 en_US.lang。

检查你的文件是否位于“assets”文件夹内。没有它的 zip
会被跳过，日志里会说明。



进度与配方
----------

如果你的脚本移除了某个配方，任何曾解锁它的进度会继续正常工作，
而不会损坏。只是它没有配方可给你了，日志会点名一次。

如果你用一个新配方替换了那个配方，并希望进度解锁新配方，
请在脚本里给新配方起个名字：

    recipes.addShaped("rail", <minecraft:rail> * 16, [[...]]);

这会把它注册为 crafttweaker:rail。然后在这里放一个指向该名称的进度文件，
进度就能重新完整运作。

没有名字的话，它会被叫作类似 crafttweaker:ct_shaped-1834729103 的名称，
那是配方本身的哈希。它在你一编辑配方时就会变，而且如果在它之前
又添加了别的配方，它也可能移位，所以不能安全地让进度指向它。


rdploader 文件夹本身可以用 config/mct_resourcedatapackloader_mixin.cfg 中的
rootDirectory 选项移动或重命名。也可以用绝对路径，
需要重启。

在这个文件旁边放一个 pack.png，可以给资源包设置图标。

这个文件由模组写入，并在内容变化时更新，
所以你在里面输入的任何内容，在下次启动游戏时都会被替换。
