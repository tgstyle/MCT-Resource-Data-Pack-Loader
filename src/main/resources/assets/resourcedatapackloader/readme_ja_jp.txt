Resource Data Pack Loader
=========================

このフォルダーに入れたものは、ModやMinecraft自身が提供するものを置き換え
ます。シングルプレイでもサーバーでも、すべてのワールドに適用されます。有効に
するための操作は必要ありません。


オーバーライドだけではありません
--------------------------------

ここに置くパックでは、JSONファイルから新しいブロック、アイテム、バイオーム、
さらにはディメンション全体を定義できます。何を生成するか、どこに生成するかを
決めたり、鍵やモブの討伐でディメンションを閉ざしたり、ワールドの陸地をあらか
じめ作っておいて、チャンクの読み込みを誰も待たなくて済むようにしたりもできま
す。Modに同梱されているHOWTO.mdに、そのすべてが書かれています。


ファイルの追加方法
------------------

Modのjarを開き、変更したいファイルを見つけて、そのパスを「assets」以降だけコピ
ーします。

鉄鉱石のテクスチャを置き換える場合、Minecraftのjarの中にあるファイルは次のと
おりです。

    assets/minecraft/textures/blocks/iron_ore.png

したがって、自分のファイルは次の場所に置きます。

    rdploader/assets/minecraft/textures/blocks/iron_ore.png

ルールはこれだけです。「assets」以降のパスは常にjar内のパスと同じなので、名前
の変更や移動は必要ありません。


整理のしかた
------------

ファイルをzipにまとめて、名前を付けたパックにすることもできます。

    rdploader/MyTextures.zip        (zipの最上位に「assets」を置く)

zipにするときは、フォルダーではなく中身を選んで圧縮してください。最上位が1つ
のフォルダーで、その中に「assets」が入っているzipは読み込まれず、ログにその旨
が記録されます。

rdploaderの中のフォルダーはパックとして扱われず、読み込まれません。ログにその
旨が記録されます。ばらのファイルはassetsの下に置き、パックにしたいものはzipに
してからここに入れてください。

同じファイルが2か所にある場合は、名前付きパックがばらのファイルより優先されま
す。ログには各ファイルの取得元のパックが記録されるので、どれが優先されたかい
つでも確認できます。


パックの優先順位
----------------

名前付きパックどうしに同じファイルがある場合は、zipの名前の先頭にRDPLと数字を
付けて、どちらを優先するか決めます。RDPL0が最初に読み込まれ、数字が大きいほど
後に読み込まれ、最後に読み込まれたパックが優先されます。

    rdploader/RDPL0 BaseTextures.zip
    rdploader/RDPL1 SeasonalTextures.zip

大文字でも小文字でも使えます。数字の後ろのスペース、ダッシュ、アンダースコア
は省略できます。接頭辞は、ログと/rdpl listに表示されるパック名からは取り除か
れるため、RDPL1 SeasonalTexturesはSeasonalTexturesと表示されます。


Mod API
-------

Modは、自分のjarの中にRDPLのコンテンツを入れておくことができます。rdploaderと
いう名前のフォルダーを作り、パックとまったく同じ構成にします。

    thatmod.jar
      mcmod.info
      rdploader/assets/thatmod/blocks/ruby_ore.json

これらはデフォルトであり、オーバーライドではありません。Modのパックはこのフォ
ルダーにあるどのパックよりも先に読み込まれるので、ここに置いたものが常に優先
されます。また、Modが提供できるのは、自分のmcmod.infoで宣言した名前空間の下に
あるファイルだけです。それ以外のファイルは警告を出して無視されるため、ほかの
Modや自分のコンテンツが、知らないうちに再定義されることはありません。

RDPLのコンテンツを同梱するModは、初めて検出されたときにconfig/mods.jsonに一覧
として記録されます。

    {
      "thatmod": {
        "enabled": true,
        "priority": -1
      }
    }

enabledをfalseにすると、そのModのコンテンツが無効になります。priorityを-1のま
まにすると、すべてのパックより下に置かれます。数字を指定すると、上で説明した
順序の中で、番号付きパックと並ぶ位置に入ります。ログではパックが優先順位の低
い順に並び、Modのパックには印が付くので、見えないところで読み込まれるものは
ありません。


リソースパック
--------------

デフォルトでは、ここにあるファイルは、プレイヤーがオプション画面で選ぶリソー
スパックより上に置かれるため、リソースパックでオーバーライドすることはできま
せん。これはModパックのロゴのようなものには適していますが、ほかの人に自由に
着せ替えてもらいたいテクスチャには向いていません。

RDPLの接頭辞の後ろにOかNを付けると、パックごとに指定できます。

    rdploader/RDPLO Branding          常に優先。リソースパックでは変更不可
    rdploader/RDPLN BaseTextures      リソースパックでオーバーライド可能
    rdploader/RDPL1O Seasonal         優先順位と常に優先の両方を指定

文字のないパックは、コンフィグのoverrideResourcePacksオプションに従います。
/rdpl list では、オーバーライドするパックに印が付きます。

接頭辞のないパックは、番号付きパックよりも前に、アルファベット順で読み込まれ
ます。そのため、番号付きパックは常に番号なしのパックより優先されます。

パックを削除せずに無効にするには、名前の末尾に.disabledを付けます。

    rdploader/RDPL1 SeasonalTextures.zip.disabled

そのパックは読み込まれず、ログにその旨が記録されます。接尾辞を外すと、また有
効になります。


変更できるもの
--------------

テクスチャ、モデル、ブロックステート、言語ファイル、サウンド、フォント、スプ
ラッシュテキスト、そのほかModがassetsフォルダーに入れているもの全般です。ガイ
ドブックやマニュアルもこれに含まれます。

進捗とルートテーブルも変更できます。これらはサーバー側で処理されるため、専用
サーバーでも機能します。

構造物テンプレート、つまりassets/<modid>/structuresの下の.nbtファイルです。ワ
ールドの専用のstructuresフォルダーに保存された構造物は、引き続きここにあるフ
ァイルより優先されます。また、すでに配置された構造物は、ワールドから抜けるま
で読み込まれたままです。

レシピも変更できます。Modのレシピを置き換えることも、自分のレシピを追加するこ
ともできます。レシピはゲームの起動時にしか読み込まれないため、ここで変更した
場合は、リロードではなく再起動が必要です。

ファンクション、つまりassets/<modid>/functionsの下の.mcfunctionファイルです。
Minecraftはこれらをワールド自身のデータフォルダーからしか読み込まないので、こ
こに置くと、すべてのワールドで動作するようになります。ワールドに保存されたフ
ァンクションは、引き続きここにあるファイルより優先されます。

レジストリ名の変更もできます。Modがブロックの名前を変更する前に保存したワー
ルドでも、そのブロックが失われずに残ります。次のようなファイルを、
assets/<modid>/registry_remapに置きます。

    {
      "registry": "minecraft:items",
      "mapping": { "oldmod:old_name": "newmod:new_name" }
    }

registryには、そのエントリが属するレジストリを指定します。通常はminecraft:
itemsかminecraft:blocksです。名前の変更は連鎖します。AをBに、のちにBをCにマッ
ピングすると、AはCに変わります。

すでに存在するものについても、ファイルに手を加えずにプロパティを変更できます。
assets/<yourpack>/overridesの中のファイルは、パスで対象を指定します。たとえば
overrides/minecraft/stone.jsonはminecraft:stoneを変更し、バニラのものにもModの
ものにも同じように使えます。ブロックでは、硬度、爆発耐性、明るさ、光の透過度、
滑りやすさ、サウンド、採掘に適したツールとそのレベル、可燃性を変更できます。
アイテムでは、スタック数、耐久値、容器アイテムを変更でき、どのアイテムでも、
食料値と効果を付けて食べられるようにできます。ポーションの効果も書き換えられ
ます。これらはその場で反映されます。パックを無効にして/rdpl reloadを実行すれ
ば、すべての値が元に戻り、再起動は必要ありません。「requires」に対象のModのID
を入れておくと、そのModが入っていないときは、ファイルが何も出さずに読み飛ば
されます。

プレイヤーのルートは、ゲームにそもそも名前のないものです。プレイヤーは持ち物
しかドロップしませんが、assets/<modid>/player_lootにファイルを置くと、プレイ
ヤー専用のルートテーブルを与えられます。

    {
      "table": "mypack:entities/player",
      "mode": "add",
      "rollOnKeepInventory": false
    }

「add」は、テーブルから抽選されたものを、持っていたものすべてに加えてドロップ
します。「replace」は、持ち物の代わりにそれをドロップします。
rollOnKeepInventoryは、持ち物を保持するワールドで、そもそもテーブルを抽選する
かどうかを決めます。

旗は特別です。1つの定義で2つのブロックが登録されます。1つは自分で付けた名前
のもの、もう1つは<name>_wallという名前のものです。アイテムを持つのは立てるほう
だけで、設置するときに、どちらにするかが自動で選ばれます。そのモデルは自身の
ブロックをはるかに越えて広がり、立てた状態では16に対して29.33、壁に掛けた状態
ではブロックの13下まで届きます。また、立てるほうのブロックステートは、16分割
で回転させるためにForgeの形式が必要です。正確な寸法はガイドに載っています。

ブロックのドロップは、ランダムにでき、アイテムである必要もありません。drops
リストのエントリは、重みを指定しない限り、それぞれ個別に判定されます。重みを
指定すると、それらは1つの壺を共有し、ちょうど1つだけが出ます。ブロックの代わ
りにエンティティを指定したエントリは、ブロックがあった場所にそのエンティティ
を放ちます。

テクスチャは、描く代わりにJSONで書くこともできます。PNGの名前の末尾に.jsonを
付けたファイル、たとえばtextures/blocks/panel.png.jsonを作り、16x16や16x32な
どのサイズ、1文字を1色に対応させたパレット、そして上から順に並べたその文字の
行を指定します。別のファイルでこれを拡張し、異なる色だけを指定することもでき
るので、1つの形を、画像ファイルを1枚も使わずに何度でも色違いにできます。それ
らが描いたものはここのpixelmap-cacheに保存され、マップやそのテンプレートが変
更されるたびに描き直されます。

何かを取り除くこともできます。recipe_removalsの中のファイルは、名前、名前空間、
または出力でレシピを削除します。disabledの中のファイルは、ブロックとアイテム
を登録解除せずにゲームから外すので、ワールドはIDを保ったままで、ファイルを削
除すればすべて元に戻ります。ルートインジェクションは、既存のルートテーブルを
置き換えるのではなく、プールを1つ追加します。block_dropsは、自分のものでは
ないブロックのドロップに追加するか、それを置き換えます。かまどのレシピ、燃料
の燃焼時間、鉱石辞書の名前、クリエイティブタブ、サウンドイベントも、それぞれ
専用のファイルになっています。

金床には新しい作業を教えられます。anvilsの中のファイルで、アイテム、右のスロ
ットに入れる組み合わせ相手のアイテム、そして指定したレベルで金床が提示するエ
ンチャントか結果を指定します。取り出すことで進捗を得られるようにでき、その進
捗を得るまでアイテムを使えないままにもできます。

tooltipsの中のファイルは、アイテムとブロックに灰色のツールチップ行を追加し、
エンチャント名の下に説明を表示します。

hardnessファイルは、ブロックのグループの採掘時間と爆発耐性を設定します。
exposuresファイルは、放射線のような危険要素を定義します。名前を指定したブロ
ックの近くにいる、名前を指定したアイテムを持っている、または名前を指定した
ディメンションにいるプレイヤーに影響します。影響は複数のレベルに分かれ、それ
ぞれが効果とダメージを与えます。近くのモブやプレイヤーからうつることもあれ
ば、雨とともに降ってくることもあります。

CraftTweakerとGroovyScriptは、これまでとまったく同じように動作します。これら
はこのModの後に実行されるので、スクリプトで削除または変更したものは、ここに
あるファイルより優先されます。

RDPLは、1つか2つのレシピを置き換えるには適しています。また、自分のコンテンツ
のレシピは、それと一緒にパックに入れるのがよいでしょう。モッドパック全体でレ
シピを細かく制御したい場合は、CraftTweakerとGroovyScriptのほうが向いています。
ここにあるファイルは元のものを完全に置き換えるので、材料を1つ変えたり、ルー
トのエントリを1つ外したりしたい場合は、そちらを使ってください。


新しいコンテンツの追加
----------------------

パックでは、JSONで記述した独自のブロック、アイテム、流体も追加できます。その
ためにModを書いたりビルドしたりする必要はありません。

ファイルのパスがそのまま名前になります。次の場所にあるブロックは、

    rdploader/MyPack/assets/mypack/blocks/copper_ore.json

mypack:copper_oreとして登録されます。記入したり間違えたりする名前のフィールド
はありません。実在するModがすでにその名前を登録している場合は、Modが優先され、
自分のファイルは読み飛ばされます。

最も単純なブロックは、数行で書けます。

    {
      "type": "ore",
      "material": "rock",
      "harvestTool": "pickaxe",
      "variants": {
        "copper_ore": { "meta": 0, "hardness": 3.0, "harvestLevel": 1 }
      }
    }

モデル、ブロックステート、テクスチャ、言語のエントリは、このフォルダーの
ほかのファイルと同じ方法で、これまでどおり用意する必要があります。

次のものは、それぞれassets/<yourpack>の下のフォルダーです。

    blocks           items            fluids           materials
    worldgen         furnace          fuels            oredict
    sounds           tabs             recipes          recipe_removals
    loot_tables      loot_injections  advancements     functions
    structures       registry_remap   potions          potion_types
    brewing          villagers        trades           biomes
    villages         entities         gates            dimensions
    gamerules        worldtemplates   worldintro       pathintersects
    hardness         blastplaster     player_loot      overrides
    teams            scoring          caveregions      exposures
    structuremaps    citymaps         portalframes     block_drops
    texts            anvils           cards            disabled
    celestial        raids            tooltips

ブロックには、「type」フィールドで決まる次の形があります。

    basic   ore     falling   slab    stairs   fence    door
    pane    wall    ladder    torch   crop     flower   cane
    log     leaves  sapling   vine    portal   trapdoor fence_gate
    banner  bell    container

アイテムには次の形があります。

    basic   food    drink     potion  tool     armor    seed
    potion_bottle   rocket

ポーションの種類は、バニラのポーション、スプラッシュポーション、残留ポーショ
ン、効果付きの矢に必ず現れます。これらは「醸造」と「戦闘」タブにあります。
タブはポーションの種類ではなくアイテムの属性なので、自分のタブに移す方法はあ
りません。potion_bottleアイテムは、代わりに自分専用の容器になります。ほかの
アイテムと同じようにcreativeTabを指定でき、potionTypesで挙げたポーションの種
類が入り、ガラス瓶が使えるところならどこでも醸造台で使えます。

villagers/<name>.jsonファイルは、職業と、その職業で選べる役職を定義します。
trades/*.jsonファイルは、自分のものでもMinecraftのものでも、あらゆる役職に
取引を追加します。職業、役職、取引が現れるレベルを指定します。存在しない役職
を指定すると、存在するものの一覧がログに出力されます。

entities/<name>.jsonファイルは、すでにあるエンティティを元にして新しいエンテ
ィティを作ります。元にするエンティティと、その違いを指定します。名前、スキ
ン、体力、ダメージ、移動速度、ジャンプの高さ、描画の大きさ、身に着けるもの、
狩る相手と無視する相手、そして元のエンティティのスポーンルールに引き続き従う
かどうかです。これは独自のスポーンエッグとルートテーブルを持つ別のエンティテ
ィで、元にしたものには手を加えません。村の区画に、村人の代わりに住まわせるこ
ともできます。また、独自のストレージを持たせることもできます。アイテムスロッ
ト、流体タンク、エネルギーバッファで、パイプやケーブルがつながり、プレイヤー
はスニークしながら右クリックして開きます。Galacticraftのロケットも同じように
バリエーションを作れ、rocket種類のアイテムで発射台に置けます。

villages/<name>.jsonファイルは、村が建てられる区画を追加します。自分で記述し
た農場でも、自分の.nbtテンプレートでもかまいません。同じ設定で、どのバニラの
パーツを引き続き出現させるか、村をどのくらい離して配置するか、どのバイオーム
に出現を許可するかも選べます。

worldintro/<name>.jsonファイルは、誰かがワールドに入ったとき、操作できるよう
になる前に、一連のページを再生します。絵の上をスクロールするテキスト、タイト
ルカード、スライドショーなどで、必要ならBGMも流せます。文章は、
assets/<yourpack>/textsの下のプレーンな.txtファイルです。プレイヤーごとに1回
だけ再生することも、参加のたびに再生することもできます。

teams/<name>.jsonファイルは、ゲームのスコアボード上にサイドを作ります。モブ、
プレイヤー、ワールドの一角でスポーンしたものは、現れたときにそのサイドに加わ
ります。scoring/<name>.jsonファイルは、キル数とデス数をそれらのサイドに記録
する目標です。スコアか時間でラウンドを終わらせ、順位をチャットまたはカードで
表示し、次のラウンドのためにマップをリセットすることもできます。

raids/<name>.jsonファイルは、不吉な予感の効果を持つプレイヤーが村に入ったと
き、その村にウェーブを送り込みます。ボスバーには残りの襲撃者の数が表示され、
村人は屋内に逃げ込み、襲撃者は木のドアを壊し、ウェーブが到着するたびに村の
すべての鐘が鳴ります。

cards/<name>.jsonファイルは、プレイヤーがバイオームに入ったときなど、何かが
起きたときに画面上にカードを表示します。同じフォルダーに、Mod自身のメッセー
ジの名前を付けたファイルを置くと、そのメッセージの文面を変更できます。

ワールド全体
------------

パックは、個々のものに限定されません。dimensions/<name>.jsonは、独自の地形、
バイオーム、空を持つディメンションを登録します。gates/<name>.jsonは、到達の
条件を設定します。アイテムを持っていることや、消費することなどです。portal
種類のブロックは、中に入った人を送り、誰が作ったかを記憶します。

ワールドテンプレートは、オーバーワールド自体の形も決められます。海面の高さ、
溶岩の海、地形のノイズを設定できます。これはワールドを作成するときに適用さ
れ、その後は適用されないので、すでにあるワールドはそのまま残ります。

worldtemplates/<name>.jsonは、ワールドの設定を1つのファイルにまとめるので、
パックは、十数か所のコンフィグ変更を求める代わりに、ワールドの形をまるごと
提供できます。設定できる各グループは、コンフィグのcontrolカテゴリにも従います。
これによって、パックが決めるのか、コンフィグが決めるのか、グループ自体がオフにな
ってどのパックでもオンにできないのかが決まります。

ディメンションは、頭上の見た目と挙動も設定できます。霧、光の色合い、太陽と月
の減光、雲の層、熱による揺らぎは、プレイヤー自身の画面に描かれます。天候は、雨
が降るか、雪が降るか、嵐になるか、にわか雨がどれだけ続くか、そして雨の色、
パーティクル、音、角度を決めます。

Galacticraftが入っていると、celestial/<name>.jsonは、パック独自の星系、惑
星、衛星、小惑星帯、宇宙ステーションをGalacticraftの星図に追加します。また、
galacticraftブロックを持つディメンションは、ロケットで行ける場所になります。

ワールド生成は、鉱石だけではありません。エントリは、広がりによって配置され
る形です。塊、長い鉱脈、板、晶洞、鉢、尖塔、団塊、噴出孔、地表の装飾、木ま
るごと、ツタ、複数のチャンクにまたがる帯、または自分の.nbtテンプレートを、
均等に、ある高さの周りに、フラクタルに、地形に沿って、洞窟の床や天井に、あ
るいは水中に、配置できます。


biomes/<name>.jsonファイルは、バイオームを定義します。気候と色、構成するブ
ロック、装飾、スポーンするもの、生成される場所です。その番号は自動で決めら
れ、そのワールドが最初に読み込まれたときに、ワールドに書き込まれます。その
ため、ほかに何を入れても、その後は変わりません。「id」を設定するのは、別の
ものがすでに使っていた番号をバイオームが保つ必要がある場合だけです。たとえ
ば、廃止されるModをパックが置き換える場合です。ワールドがすでに含んでいる
バイオームの名前を変更したり削除したりすると、ブロックの番号を振り直した場
合と同じように失われるので、名前の変更にはregistry_remapを使ってください。

村人の表示名は、言語キーentity.Villager.<career>で、書いたとおりの役職名だけ
を使います。このキーの空間は、Minecraftやほかのすべてのパックと共有されてい
るため、rdpltest.prospectorのように、役職名に自分の名前空間を入れてください。
影響があるのは名前だけです。村人は役職を数値として保存するので、名前を変える
と既存の村人の呼ばれ方が変わり、careersリストの順序を入れ替えると、彼らの役
職が変わります。

ポーションの種類も、ファイル名と同じように名前が付けられ、表示名は言語キー
potion.effect.<namespace>.<name>から取得されます。ほかの3つの形には、
splash_potion.effect.、lingering_potion.effect.、tipped_arrow.effect.を使い
ます。


Rubicワールド
-------------

ワールドテンプレートでは、256ブロックの柱ではなく、立方体で作られたワールド
を要求できます。するとワールドは上下の両方向に広がり、0よりずっと下の床と、
255よりずっと上の天井ができ、その全体に地形、洞窟、鉱石が作られます。中での
遊び方はいつもと同じです。掘り、建て、明かりをつけ、移動するのも同じで、バ
ニラの生成範囲は、より高いワールドの中でもこれまでの形を保つため、地形を生
成するModは、以前と同じ場所に地形を作ります。

パックが利用できるのは次のものです。ワールドの高さ（ワールドを作るときに1
回だけ設定）、バニラの範囲の下にある深層ワールド（指定した石の中に、ノイズ
洞窟、帯水層、帯状の鉱脈ができる）、洞窟エリア（洞窟バイオームに当たるパッ
クの仕組みで、地下に3次元で描かれ、独自の床、天井、水位、モブ、構造物を持
つ）、積み重ねたディメンション（あるワールドの底から落ちると下の次のワール
ドに移り、上から出ると戻ってくる）、そして除外したディメンション（同じセー
ブの中で、通常のワールドのままにする）です。

内部では、ワールドは16×16×16のキューブとして、バニラのものと並ぶ専用のリー
ジョンファイルに保存され、それぞれ独立して生成、読み込み、保存されます。ラ
イトエンジンも、この形に合わせて書かれています。ワールドの高さが256ブロッ
クだというバニラの前提は、ビルドの上限や奈落の判定から、経路探索、ポータル、
ビーコン、マップ、描画に至るまで、支障が出るあらゆる箇所に修正が入っていま
す。ほかのModのジェネレーターには、通常と同じに見える256ブロックの範囲だけ
が見えるので、そのModの地形も機能します。

設定、ワールドが取れる高さ、これと一緒には動かないModについては、HOWTO.md
に書かれています。


メタ値に関する注意
------------------

すべてのバリアントにはメタ値の番号があり、ワールドのファイルに保存されるの
はその番号です。ワールドにすでにあるバリアントの番号を振り直すと、そのブロ
ックは別のものに変わってしまいます。新しいバリアントは末尾に追加し、既存の
番号は絶対に振り直さないでください。

1つのブロックが持てるバリアントは16個です。メタデータの4ビットで表せる数が
それだからです。ハーフブロックは8個です。1ビットが上下を表すためです。階段、
はしご、松明、作物は1個です。向きや成長段階が残りを使うためです。アイテムは
それほど厳しくなく、番号を飛ばしても構いません。


できないこと
------------

ここで書くのは、ものが何であるかであり、時間とともに何をするかではありませ
ん。タイルエンティティ、GUI、毎ティック動くコードが必要なものは、これまでど
おり本物のModが必要です。例外は2つあります。containerという種類のブロック
は、専用の画面を持つインベントリを保持できます。また、エンティティのバリエ
ーションにはストレージを持たせられます。機械は対象外ですが、鉱石、フェンス、
食べ物、流体は対象です。


他バージョンのパック
--------------------

このModの1.20.1、1.21.1、26.xのラインで作られたパックは、ここでも読み込ま
れます。zipは1回だけ、その内部でversions/1.12.2フォルダーに変換され、新し
いバージョン向けのファイルはそのまま残るため、同じzipがすべてのバージョン
で使い続けられます。


変更の確認
----------

F3+Tを押すと、テクスチャ、モデル、言語ファイル、進捗、ルートテーブルがリロ
ードされます。サーバーでは、/reloadと入力すると同じことができます。レシピ
は先ほど書いたとおり例外で、起動時にしか読み込まれないため、レシピを変更し
たら再起動が必要です。

ファイルを新しく追加したり削除したりした場合は、代わりに/rdpl reloadを使い
ます。すでにあったファイルを編集しただけなら、F3+Tで足ります。

/rdpl reload texturesはテクスチャだけをリロードします。大きなパックでは、
F3+Tよりずっと速くなります。models、languages、sounds、shadersも同じように
使えます。名前を付けなければ、フォルダーを再スキャンしてすべてをリロードし
ます。

/rdpl listは、読み込まれているすべてのパックと、その中身を表示します。パック
をクリックすると、詳細が見られます。

/rdpl which minecraft:textures/blocks/stone.pngは、そのファイルをどのパック
が提供しているか、またその下でどのパックが隠されているかを表示します。

/rdpl config unusedは、インストールされているどのパックももう定義していない
オプションファイルを、rdploader/configの中から一覧にします。/rdpl config
pruneはそれらを削除します。/rdpl pixelmapは、ピクセルマップがどのような結
果になったかを表示します。/rdpl biome listとhereはバイオームについて教えて
くれます。/rdpl teamと/rdpl roundは、パックが定義するサイドとラウンド用で
す。

これらはオペレーターでなくても使えます。自分のコンピューターにあるフ
ァイルを読むだけだからです。専用サーバーでは、/rdplserver reloadでサーバー
側のコピーを再スキャンします。


うまく動かないとき
------------------

まずログを確認してください。進捗、ルートテーブル、レシピ、ファンクション、
構造物は、どのパックから読み込まれたかとともにログに記録され、おかしな点は
理由を添えて警告として記録されます。

テクスチャなどのアセットについては、/rdpl unusedで、パック内にあって、まだ
どこからも要求されていないファイルを一覧にできます。多くの場合、パスの打ち
間違いです。ゲームの読み込みが終わってから実行してください。プレイしてい
る言語以外の言語ファイルなど、必要になったときにしか読み込まれないファイ
ルもあることに注意してください。

大文字と小文字は区別されます。ファイルがStone.pngで、ゲームが求めたのが
stone.pngでも読み込まれますが、名前を変更するよう警告が出ます。必ず名前を
変更してください。このMod以外では、そのファイルがまったく見つからないため
です。言語ファイルでは特によくあるミスで、正しくはen_us.langであり、
en_US.langではありません。

ファイルが「assets」フォルダーの中にあることを確認してください。ないzipは
読み込まれず、ログにその旨が記録されます。



進捗とレシピ
------------

スクリプトでレシピを削除しても、それを解除していた進捗は壊れずに動き続けま
す。ただ、与えるレシピが残っていないだけで、ログにはそれが1回記録されます。

そのレシピを新しいものに置き換え、進捗で新しいほうを解除したい場合は、スク
リプトで新しいレシピに名前を付けてください。

    recipes.addShaped("rail", <minecraft:rail> * 16, [[...]]);

これでcrafttweaker:railとして登録されます。次に、その名前を指す進捗ファイル
をここに置けば、進捗は最初から最後までまた正しく動きます。

名前がないと、crafttweaker:ct_shaped-1834729103のような名前が付きます。これ
はレシピ自体のハッシュです。レシピを編集した途端に変わり、その前に別のレシ
ピが追加されるとずれることもあるため、進捗の指定先としては安全ではありませ
ん。


rdploaderフォルダー自体は、config/mct_resourcedatapackloader_mixin.cfgの
rootDirectoryオプションで、移動も名前の変更もできます。絶対パスも使えます。
再起動が必要です。

このファイルの隣にpack.pngを置くと、パックにアイコンを付けられます。

このファイルはModによって書き込まれ、内容が変わるたびに最新の状態に更新され
ます。そのため、ここに書き込んだものは、次にゲームを起動したときに置き換え
られます。
