Resource Data Pack Loader
=========================

このフォルダーに入れたものは、ModやMinecraft自身が提供するものを
置き換えます。シングルプレイでもサーバーでも、すべてのワールドに適用され、
有効にする操作は必要ありません。


オーバーライドだけではありません
--------------------------------

ここに置くパックでは、JSONファイルから新しいブロック、アイテム、バイオーム、
さらにはディメンション全体を定義できます。何を生成するか、どこに生成するかも
決められます。ディメンションにキーや倒すべきモブによるロックをかけたり、
ワールドの陸地を事前に生成してチャンクの読み込みを待たずに済むようにもできます。
Modに同梱されているHOWTO.mdに、そのすべてが書かれています。


ファイルの追加方法
------------------

Modのjarを開き、変更したいファイルを見つけて、'assets' または 'data' から
始まるパスをコピーします。

鉄鉱石のテクスチャを置き換える場合、Minecraftのjar内のファイルは次のとおりです。

    assets/minecraft/textures/block/iron_ore.png

したがって、置き換えるファイルはここに置きます。

    rdploader/assets/minecraft/textures/block/iron_ore.png

ルートテーブルは assets ではなく data の下にあり、同じ方法で置き換えられます。

    data/minecraft/loot_tables/blocks/iron_ore.json
    rdploader/data/minecraft/loot_tables/blocks/iron_ore.json

ルールはこれだけです。'assets' または 'data' より後ろのパスは、常にjar内の
パスと同じなので、名前を変えたり移動したりする必要はありません。


パックの整理
------------

ファイルをまとめて、名前付きのパックとして zip にすることもできます。

    rdploader/MyTextures.zip        (zipの最上位に 'assets' か 'data' を置く)

zip にするときは、フォルダーごとではなく、その中身を選んで圧縮してください。
最上位が1つのフォルダーで、その中に 'assets' や 'data' がある zip は
スキップされ、ログにその旨が記録されます。

rdploader内のフォルダーはパックではないため、スキップされ、ログにその旨が
記録されます。個別のファイルは assets または data の下に置き、パックにする場合は
zip にしてからここに入れてください。

同じファイルが2か所にある場合、個別のファイルより名前付きパックが優先されます。
どちらが優先されたかは /rdpl which で確認できます。


パックの優先順位
----------------

名前付きパックの間で同じファイルが重複する場合は、zip の名前の先頭に RDPL と
数字を付けて、どちらを優先するか決めます。RDPL0 が最初に読み込まれ、数字が
大きいほど後に読み込まれ、最後に読み込まれたパックが優先されます。

    rdploader/RDPL0 BaseTextures.zip
    rdploader/RDPL1 SeasonalTextures.zip

大文字でも小文字でも使え、数字の後ろのスペース、ダッシュ、アンダースコアは
省略できます。ログや /rdpl list では、パック名から接頭辞が取り除かれて表示される
ので、RDPL1 SeasonalTextures は SeasonalTextures と表示されます。


Mod API
-------

Modは、自身のjarの中に rdploader という名前のフォルダーを作り、パックとまったく
同じ構成でRDPLのコンテンツを同梱できます。

    thatmod.jar
      META-INF/mods.toml
      rdploader/assets/thatmod/textures/block/ruby_ore.png

これらはオーバーライドではなく、デフォルトです。Modのパックは、このフォルダーの
どのパックよりも下に読み込まれるため、ここに置いたものが常に優先されます。
また、Modが提供できるのは、自身の mods.toml で宣言した名前空間の
ファイルだけです。それ以外は警告とともに無視されるので、ほかのModや
ここにあるコンテンツが、こっそり再定義されることはありません。

パックを同梱するModは、初めて検出されたときに config/mods.json に一覧として
記録されます。

    {
      "thatmod": {
        "enabled": true,
        "priority": -1
      }
    }

enabled を false にすると、そのModのコンテンツが無効になります。priority を -1
のままにすると、すべてのパックの下に置かれます。数字を指定すると、上記の順序の
中で、番号付きパックと並んで位置が決まります。ログではパックが優先順位の低い
ものから順に記録され、Mod自身のパックには印が付くので、見えないまま読み込まれる
ものはありません。


リソースパック
--------------

デフォルトでは、ここにあるファイルは、プレイヤーがオプション画面で選ぶリソース
パックより上に置かれるため、リソースパックでオーバーライドすることはできません。
これはModパックのロゴのようなものには適していますが、利用者が自由に着せ替えでき
るようにしたいテクスチャには向いていません。

パックごとに決めるには、RDPL の接頭辞の後に O または N を付けます。

    rdploader/RDPLO Branding          常に優先。リソースパックでは変更できない
    rdploader/RDPLN BaseTextures      リソースパックでオーバーライドできる
    rdploader/RDPL1O Seasonal         優先順位を指定し、かつ常に優先

文字を付けないパックは、コンフィグのoverrideResourcePacksオプションに従います。
オーバーライドするパックには、/rdpl list で印が付きます。

データパックにも同じルールが適用されます。N を付けたパックは、ワールド自身の
datapacks フォルダーにあるデータパックより下に、O を付けたパックは上に
置かれます。

接頭辞のないパックは、すべての番号付きパックより前に、アルファベット順で読み
込まれるため、番号付きパックが必ず番号なしのパックより優先されます。

パックを削除せずに無効にするには、名前の末尾に .disabled を付けます。

    rdploader/RDPL1 SeasonalTextures.zip.disabled

そのパックはスキップされ、ログにその旨が記録されます。接尾辞を外すと、再び有効
になります。


変更できるもの
--------------

テクスチャ、モデル、ブロックステート、言語ファイル、サウンド、フォント、
スプラッシュテキスト、そのほかModが assets フォルダーに置いているもの
(ガイドブックやマニュアルなど)。

進捗、ルートテーブル、レシピ、タグ、ファンクション、構造物テンプレート、
そのほかModが data フォルダーに置いているもの。これらはサーバー側のものなので、
専用サーバーでも機能し、変更は /reload で反映されます。

ものを取り除くこともできます。recipe_removals 内のファイルは、名前、名前空間、
または出力を指定してレシピを削除します。disabled 内のファイルは、登録を解除
せずにブロックとアイテムをプレイから外すので、ワールドのIDは保たれ、ファイル
を削除すればすべて元に戻ります。ルートインジェクションは、既存のルートテーブル
を置き換えずにプールを追加し、block_drops は、自分のものではないブロックの
ドロップを追加または置き換えます。かまどのレシピ、燃料の燃焼時間、クリエイティブ
タブ、サウンドイベントも、それぞれ独立したファイルです。

金床に新しい作業を教えることもできます。anvils 内のファイルには、アイテムと、
右スロットに入れる組み合わせのアイテム、そして指定したレベルに対して金床が提示
するエンチャントまたは結果を指定します。取り出すと進捗を達成でき、その進捗を
達成するまでアイテムを使えないままにもできます。

tooltips 内のファイルは、アイテムとブロックに灰色のツールチップ行を追加し、
エンチャント名の下に説明を表示します。

hardness ファイルは、ブロックのグループに対して採掘時間と爆発耐性を設定します。
exposures ファイルは、放射線のような危険要素を定義します。指定したブロックの
近く、指定したアイテムの所持、指定したディメンションにいるプレイヤーに影響し、
各レベルで効果とダメージを与えます。近くのモブやプレイヤーからうつることも、
雨とともに降ってくることもあります。


新しいコンテンツの追加
----------------------

パックでは、独自のブロック、アイテム、流体を JSON で記述して追加することもでき
ます。Modを書いたりビルドしたりする必要はありません。

定義は data の下に、種類ごとのフォルダーに置きます。"variants" 内の各キーが名前
になるので、次のファイルに

    rdploader/data/mypack/blocks/ores.json

ruby_ore というバリアントを書くと、mypack:ruby_ore が登録されます。ファイル名は
ものをまとめるだけのものです。実際のModがすでにその名前を登録している場合は、
Modが優先され、自作のバリアントはスキップされます。

最も単純なブロックは、数行で書けます。

    {
      "type": "ore",
      "material": "rock",
      "harvestTool": "pickaxe",
      "variants": {
        "ruby_ore": { "hardness": 3.0, "harvestLevel": 1 }
      }
    }

モデル、ブロックステート、テクスチャ、言語エントリは、このフォルダー内のほかの
ファイルと同じ方法で、assets の下に用意する必要があります。

次のものは、それぞれ data/<yourpack> の下のフォルダーです。

    blocks           items            fluids           materials
    tabs             sounds           biomes           worldgen
    caveregions      dimensions       worldtemplates   worldintro
    gates            gamerules        teams            scoring
    raids            entities         hardness         anvils
    exposures        overrides        villages         pathintersects
    structuremaps    citymaps         portalframes     blastplaster
    structures       recipes          recipe_removals  furnace
    fuels            brewing          potions          potion_types
    villagers        trades           loot_tables      loot_injections
    block_drops      player_loot      advancements     functions
    tags             registry_remap   cards            disabled
    tooltips

ブロックには、"type" フィールドで指定する次の形があります。

    basic   ore     falling   slab    stairs   fence    door
    pane    wall    ladder    torch   crop     flower   cane
    log     leaves  sapling   vine    portal   trapdoor fence_gate
    banner  bell    container

アイテムには次の形があります。

    basic   food    drink     potion  tool     armor    seed
    potion_bottle   container

ポーションの種類は、言語キー item.minecraft.potion.effect.<baseName> で名前が
付けられ、ほかの形では potion の代わりに splash_potion、lingering_potion、
tipped_arrow を使います。potion_bottle アイテムは、それらを入れる独自の
容器です。ほかのアイテムと同じく creativeTab を取り、potionTypes に
指定したポーションの種類を保持します。

villagers/<name>.json ファイルは職業を定義します。trades/*.json ファイルは、
自作かMinecraftのものかを問わず、任意の職業に取引を追加し、その職業と、
取引が現れるレベルを指定します。

entities/<name>.json ファイルは、すでにあるエンティティから新しいエンティティを
作ります。元にするエンティティと、その違いを指定します。名前、見た目、体力と
ダメージ、動き方、戦い方、ドロップするものなどです。これは独自のスポーンエッグと
ルートテーブルを持つ独立したエンティティで、元のエンティティには影響しません。
また、アイテムスロット、流体タンク、エネルギーバッファといった独自のストレージ
を持たせることもできます。パイプやケーブルがそこにつながり、プレイヤーはスニーク
しながら右クリックして開きます。

villages/<name>.json ファイルは、都市や村が自作の .nbt テンプレートから
建てられる区画を追加します。raids/<name>.json ファイルは、プレイヤーが
不吉な予感を村に持ち込んだときに、村へウェーブを送り込みます。

cards/<name>.json ファイルは、プレイヤーがバイオームに入ったときなど、何かが起き
たときに画面上にカードを表示します。同じフォルダーにあるModのメッセージ名のファ
イルは、そのメッセージの文面を変更します。

worldintro/<name>.json ファイルは、誰かがワールドに入ったとき、操作が可能になる
前に、一連のページを再生します。文章は assets/<yourpack>/texts の下にある
プレーンな .txt ファイルです。プレイヤーごとに1回だけ再生することも、参加する
たびに再生することもできます。

teams/<name>.json ファイルは、ゲームのスコアボード上にサイドを用意して、何が
そこに加わるかを指定します。scoring/<name>.json ファイルは、それらのサイドに
ポイントを与える目標で、試合の終わり方も決めます。


ワールド全体
------------

パックは、単体のものだけに限られません。dimensions/<name>.json は、独自の地形、
バイオーム、空を持つディメンションを登録します。gates/<name>.json は、アイテム
を持つ、または消費するといった、そこへ行くための条件を付けます。portal 種類の
ブロックは、歩いて入った者を別のディメンションへ送り、portalframes を使うと
プレイヤーが自分のフレームを作って点火できます。

worldtemplates/<name>.json は、ワールドの設定を1つのファイルにまとめるので、
パックは多くのコンフィグ編集を求めずに、ワールドの形を一度に提供できます。
海面の高さや、海が溶岩かどうかなど、オーバーワールド自体の形を決めることも
できます。

ディメンションでは、頭上の見え方や挙動も設定できます。霧、光の色合い、太陽と月の
減光、雲の層、陽炎は、プレイヤーの画面に描画されます。天候は、雨、雪、嵐のどれが
降るか、にわか雨の長さ、そして雨の色、パーティクル、音、角度を決めます。

worldgen は鉱石だけではありません。エントリは、自分のブロックの小さな塊から
自作の .nbt テンプレートまで、さまざまな形を配置し、その頻度、高さ、現れる
バイオームを決めます。

biomes/<name>.json ファイルはバイオームを定義します。気候と色、構成する
ブロック、装飾するもの、そこでスポーンするもの、そして生成される場所です。


対応範囲の限界
--------------

ここで記述するのは、ものが何であるかであり、時間とともに何をするかではありま
せん。ブロックエンティティ、画面、毎ティック動くコードが必要なものは、やはり
本物のModが必要です。例外は2つあり、container 種類のブロックは独自の画面を持つ
インベントリを持ち、エンティティのバリアントはストレージを持てます。機械は
作れませんが、鉱石、フェンス、食べ物、流体なら作れます。


他バージョンのパック
--------------------

このModの1.12.2版向けに作られたパックは、そのままここで読み込まれます。zip は
一度だけ、その内部でこのバージョン用の versions フォルダーに変換され、1.12.2
のファイルはそのまま残るので、同じ zip がどのバージョンでも使い続けられます。


変更の確認
----------

F3+T を押すと、テクスチャ、モデル、言語ファイル、そのほか assets の下のものが
すべてリロードされます。サーバーの場合や data の下のものは、/reload と入力
します。

ファイルを新しく追加したり削除したりした場合は、代わりに /rdpl reload を使い
ます。すでにあるファイルの編集だけなら、F3+T または /reload で十分です。

/rdpl list は、読み込まれたすべてのパックとその内容を表示します。パックに
カーソルを合わせると、その内容が表示されます。

/rdpl which minecraft:textures/block/stone.png は、どのパックがそのファイルを
提供しているか、その下で隠されているパックがどれかを表示します。

/rdpl config unused は、rdploader/config 内にある、インストール済みのどのパック
も定義しなくなった設定ファイルを一覧表示し、/rdpl config prune はそれらを削除
します。/rdpl pixelmap はピクセルマップの結果を表示し、/rdpl biome list と
here はバイオームについて教えてくれます。

これらは自分のコンピューター上のファイルを読むだけなので、OP権限がなくても
使えます。専用サーバーでは、/rdplserver reload がサーバー側のコピーを再スキャン
し、/rdplserver list、which、unused がサーバーについて答えます。


うまく動かないとき
------------------

まずログを確認してください。logs/rdpl.log には、読み込まれたパックと、スキップ
されたパックがその理由とともにすべて記録されており、問題があれば理由を添えた
警告としてログに残ります。

/rdpl unused は、まだ何からも要求されていない、パック内のファイルを一覧表示し
ます。多くの場合、パスの打ち間違いが原因です。ゲームの読み込みが完了してから
実行してください。ただし、普段プレイしている言語以外の言語ファイルのように、
必要になったときにだけ読み込まれるファイルもあります。

大文字と小文字は区別されます。ファイルが Stone.png で、ゲームが stone.png を
要求した場合も読み込まれますが、名前を変更するよう警告が出ます。必ず名前を
変更してください。このMod以外では、そのファイルはまったく見つからないからです。
言語ファイルで特につまずきやすく、正しくは en_us.json で、en_US.json ではあり
ません。

ファイルが 'assets' または 'data' フォルダーの中にあるか確認してください。
どちらもない zip はスキップされ、ログにその旨が記録されます。


進捗とレシピ
------------

スクリプトが追加または置き換えるレシピは、スクリプトが付けた名前で識別されます。
進捗でそれをアンロックするには、そのレシピを指定した進捗ファイルをここに置く
と、進捗が最後まで再び機能します。

そのようなレシピには、スクリプトで固定の名前を付けてください。自動で付く名前は、
レシピを編集した途端に変わることがあるため、進捗の参照先としては安全ではありま
せん。


rdploader フォルダー自体は、config/resourcedatapackloader-common.toml の
rootDirectory オプションで移動や名前の変更ができます。絶対パスも使えます。
再起動が必要です。

このファイルの隣に pack.png を置くと、パックにアイコンが付きます。

このファイルはModによって書き出され、変更があるたびに最新の内容に更新される
ため、ここに入力した内容は、次にゲームを起動したときに置き換えられます。
