Resource Data Pack Loader
=========================

放進這個資料夾的任何內容，都會取代模組或 Minecraft 本身提供的內容。
它適用於每個世界，單人遊戲與伺服器皆然，
不需要開啟任何開關。


不只是覆寫
----------

這裡的資源包還能用 JSON 檔案定義新的方塊、物品、生態域，乃至整個維度，
決定要生成什麼、在哪裡生成，用鑰匙或必須擊殺的生物替維度上鎖，
還能預先生成世界的陸地，讓沒有人需要等待區塊載入。
隨模組一起發布的 HOWTO.md 涵蓋了這一切。


如何新增檔案
------------

開啟模組的 jar，找到你想修改的檔案，從「assets」開始複製它的路徑。

要取代鐵礦石的材質，Minecraft jar 裡的檔案是：

    assets/minecraft/textures/blocks/iron_ore.png

那麼你的版本放在這裡：

    rdploader/assets/minecraft/textures/blocks/iron_ore.png

這就是全部的規則。「assets」之後的路徑一律與 jar 內的路徑相同，
所以不需要重新命名或移動任何東西。


保持整潔
--------

你也可以把檔案歸入一個具名的資源包，以 zip 打包：

    rdploader/MyTextures.zip        （zip 的最上層要直接是「assets」）

打包時，請選取裡面的內容再壓縮，不要壓縮外面的資料夾。
如果 zip 的最上層是一個包著「assets」的單一資料夾，
它會被略過，日誌裡會說明。

rdploader 裡的資料夾不算資源包，會被略過，日誌裡會說明。
零散的檔案請放在 assets 底下，資源包請先壓縮成 zip 再放進來。

同一個檔案出現在兩個地方時，具名的資源包優先於零散的檔案。
日誌會寫明每個檔案來自哪個資源包，所以你隨時能看出哪一個勝出。


資源包優先順序
--------------

如果兩個具名的資源包含有同一個檔案，可以在 zip 名稱前面加上
RDPL 和一個數字來控制哪一個勝出。RDPL0 最先載入，數字越大
載入越晚，最後載入的資源包勝出：

    rdploader/RDPL0 BaseTextures.zip
    rdploader/RDPL1 SeasonalTextures.zip

大小寫均可，數字後面的空格、連字號或底線可有可無。
前綴在日誌和 /rdpl list 裡會被去掉，所以
RDPL1 SeasonalTextures 會顯示為 SeasonalTextures。


模組 API
--------

模組可以在自己的 jar 裡攜帶 RDPL 內容，放在名為 rdploader 的
資料夾中，版面配置與資源包完全相同：

    thatmod.jar
      mcmod.info
      rdploader/assets/thatmod/blocks/ruby_ore.json

這些是預設值，不是覆寫。模組的資源包載入順序低於這個資料夾裡的
所有資源包，所以你放在這裡的內容會勝出，而模組只能在它自己的
mcmod.info 裡宣告過的命名空間底下提供檔案。其他內容會被
忽略並給出警告，因此沒有任何模組能悄悄重新定義別的模組或你的內容。

每個附帶這種內容的模組，在第一次被發現時都會列入
config/mods.json：

    {
      "thatmod": {
        "enabled": true,
        "priority": -1
      }
    }

把 enabled 設為 false 即可關閉該模組的內容。priority 維持 -1 則
一律墊在最底層，也可以給一個數字，讓它依照上面的順序與
編號的資源包並列。日誌裡會由低到高列出資源包，模組自帶的會有
標記，所以不會有你看不到的內容被載入。


資源包：誰優先
--------------

預設情況下，這裡的檔案位於玩家在選項畫面中選取的資源包之上，
所以資源包無法覆寫它們。這對整合包標誌之類的東西是對的，
對希望玩家能自行替換的材質則不對。

在 RDPL 前綴後面加上 O 或 N，可以逐個 RDPL 包決定：

    rdploader/RDPLO Branding          一律勝出，資源包無法更動
    rdploader/RDPLN BaseTextures      資源包可以覆寫它
    rdploader/RDPL1O Seasonal         有優先順序，並且一律勝出，兩者兼備

沒有字母的 RDPL 包遵循設定中的 overrideResourcePacks 選項，
/rdpl list 會標出會覆寫的那些。

沒有前綴的 RDPL 包會先於所有編號的 RDPL 包載入，並依字母順序排列，
所以編號的 RDPL 包一律勝過沒有編號的。

想停用某個 RDPL 包又不想刪除它，在名稱結尾加上 .disabled：

    rdploader/RDPL1 SeasonalTextures.zip.disabled

該 RDPL 包會被略過，日誌裡會說明。移除後綴即可重新啟用。


你可以變更的內容
----------------

材質、模型、方塊狀態、語言檔案、音效、字型、閃爍標語，以及模組在
assets 資料夾裡存放的其他一切，例如指南書或手冊。

進度與戰利品表。它們屬於伺服端，所以在專用伺服器上同樣有效。

結構範本，也就是 assets/<modid>/structures 底下的 .nbt 檔案。儲存在
世界自己 structures 資料夾裡的結構仍然優先於這裡的檔案，已經放置過的
結構在你離開世界之前會維持載入。

配方，包括取代模組的配方或新增你自己的。配方只在遊戲啟動時載入，
所以這裡的修改需要重新啟動，而不是重新載入。

函式，也就是 assets/<modid>/functions 底下的 .mcfunction 檔案。
Minecraft 只會從世界自己的 data 資料夾讀取它們，所以放在這裡能讓
它們在每個世界生效。儲存在世界裡的函式仍然優先於這裡的檔案。

登錄表重新命名，這樣在模組重新命名了某個方塊之前儲存的世界，
會保留該方塊而不是遺失它。把檔案放進 assets/<modid>/registry_remap：

    {
      "registry": "minecraft:items",
      "mapping": { "oldmod:old_name": "newmod:new_name" }
    }

登錄表是該項目所屬的那一個，通常是 minecraft:items 或 minecraft:blocks。
重新命名可以串連，先把 A 對應到 B、之後又把 B 對應到 C，就會讓 A 變成 C。

已經存在的事物的屬性，無需更動它們的檔案。assets/<yourpack>/overrides
裡的檔案以路徑指明目標，所以 overrides/minecraft/stone.json 修改的是
minecraft:stone，原版或模組方塊皆可。方塊可設定硬度、爆炸抗性、光照、
透光度、滑度、音效、採集工具與等級，以及可燃性。物品可設定堆疊數量、
耐久度和容器物品，任何物品都可以變成可食用，並帶有食物數值和效果。
藥水的效果也可以重寫。這些是即時生效的：停用資源包並執行
/rdpl reload，每個數值都會彈回原樣，無需重新啟動。把所屬模組的 id
寫進「requires」，這樣該模組未安裝時，檔案會被悄悄略過。

玩家戰利品，是遊戲裡根本沒有對應名稱的東西。玩家只會掉落自己的物品欄，
別無其他，所以 assets/<modid>/player_loot 裡的檔案會給他們一張
自己的戰利品表：

    {
      "table": "mypack:entities/player",
      "mode": "add",
      "rollOnKeepInventory": false
    }

「add」會在他們攜帶的一切之外，額外掉落這張表抽出的東西，「replace」則用它
取代物品欄的掉落，rollOnKeepInventory 決定在保留物品欄的世界裡
是否還要抽取這張表。

旗幟是個例外。一份定義會登錄兩個方塊，你的和另一個名為 <name>_wall 的，
只有立著的那個有物品，放置時由它在兩者之間選擇。它的模型遠遠超出
自己所在的方塊，立著時達到 16 中的 29.33，掛在牆上時則在方塊下方
13，立著的方塊狀態需要 Forge 的格式才能以十六分之一為單位旋轉。
指南裡有完整的尺寸。

方塊的掉落物可以是隨機的，也不必是物品。它的 drops 清單裡的項目各自
獨立判定，除非你給它們權重，這樣它們就共用一個池，恰好有一個會出現。
指明實體而不是方塊的項目，會在方塊原本的位置放出那個實體。

材質可以用 JSON 寫出來，而不必繪製。把檔案依 PNG 命名並在結尾加上
.json，例如 textures/blocks/panel.png.json，再給它一個尺寸，如 16x16 或
16x32，一個「一個字元對應一種顏色」的調色盤，以及由這些字元組成、
由上而下的若干列。另一個這樣的檔案可以擴充它，只寫出想要不同的顏色，
所以同一種形狀可以任意多次地換色，而不需要任何一張圖片檔案。它們繪製出的
內容儲存在這裡的 pixelmap-cache 中，每當某張圖或它的範本改變時就會重新繪製。

也可以把東西移除。recipe_removals 裡的檔案依名稱、命名空間或產物刪除
配方，disabled 裡的檔案把方塊和物品移出遊戲而不取消登錄，
所以世界保留原有的 id，刪除該檔案就能讓一切恢復。戰利品注入
會向既有的戰利品表加入一個池，而不是取代它，block_drops 則為
不屬於你的方塊新增或取代掉落物。熔爐配方、燃料燃燒時間、礦物辭典
名稱、創造模式分頁和音效事件也各有自己的檔案。

鐵砧也可以學會新的操作。anvils 裡的檔案指明一個物品、與它搭配放在
右側欄位的物品，以及鐵砧在指定等級下提供的附魔或結果。取出成品
可以獲得一項進度，物品也可以在獲得這項進度之前一直無法使用。

hardness 檔案為一組方塊設定挖掘時間和爆炸抗性，exposures 檔案
則定義輻射之類的危險：它作用於靠近指定方塊、攜帶指定物品或
處於指定維度的玩家，分為若干等級，每級施加效果和傷害，
也可以從附近的生物和玩家身上染上，或隨雨水降下。

CraftTweaker 和 GroovyScript 仍然和以前完全一樣地運作。它們在本模組
之後執行，所以你的腳本移除或修改的內容會勝過這裡的檔案。

RDPL 適合取代一兩個配方，而你自己內容的配方應當放在旁邊的資源包裡。
如果要在整個整合包範圍內完全控制配方，CraftTweaker 和 GroovyScript 是
更好的選擇。這裡的檔案會把原檔案整個取代，所以要改一個材料或去掉
一個戰利品項目，請用它們。


新增內容
--------

資源包還可以新增自己的方塊、物品和流體，以 JSON 描述。你
不需要編寫或建構模組。

檔案的路徑就是它的名稱。位於

    rdploader/MyPack/assets/mypack/blocks/copper_ore.json

的方塊會登錄為 mypack:copper_ore。沒有需要填寫或可能寫錯的名稱欄位。
如果某個真正的模組已經登錄了該名稱，模組勝出，你的檔案會被略過。

最簡單的方塊只要幾行：

    {
      "type": "ore",
      "material": "rock",
      "harvestTool": "pickaxe",
      "variants": {
        "copper_ore": { "meta": 0, "hardness": 3.0, "harvestLevel": 1 }
      }
    }

模型、方塊狀態、材質和語言項目仍依這個資料夾裡其他檔案的方式提供。

下面每一項都是 assets/<yourpack> 底下的一個資料夾：

    blocks           items            fluids           materials
    worldgen         furnace          fuels            oredict
    sounds           tabs             recipes          recipe_removals
    loot_tables      loot_injections  advancements     functions
    structures       registry_remap   potions          potion_types
    brewing          villagers        trades           biomes
    villages         entities         gates            dimensions
    gamerules        worldtemplates   worldintro       pathintersects
    hardness         blastplaster     player_loot      overrides
    teams            scoring          caveregions      exposures
    structuremaps    citymaps         portalframes     block_drops
    texts            anvils           cards            disabled
    celestial        raids

方塊有以下幾種型態，由「type」欄位決定：

    basic   ore     falling   slab    stairs   fence    door
    pane    wall    ladder    torch   crop     flower   cane
    log     leaves  sapling   vine    portal   trapdoor fence_gate
    banner  bell    container

物品則有以下幾種：

    basic   food    drink     potion  tool     armor    seed
    potion_bottle   rocket

藥水類型一律會出現在原版的藥水、噴濺藥水、滯留藥水和藥水箭上，它們位於
釀造與戰鬥分頁。分頁是物品的屬性，而不是藥水類型的屬性，所以
沒有辦法把它們挪到你自己的分頁裡。potion_bottle 物品則是你自己的
容器：它和其他物品一樣帶有 creativeTab，在 potionTypes 裡列出你指定的
藥水類型，釀造台在任何玻璃瓶能用的地方都會接受它。

villagers/<name>.json 檔案定義一種職業及其提供的職涯。trades/*.json 檔案
為任何職涯新增交易，無論是你的還是 Minecraft 的，並指明職業、職涯和
交易出現的等級。如果指定的職涯不存在，日誌會列出存在的那些。

entities/<name>.json 檔案以既有的實體做出一個新實體。它指明所根據的
實體，以及不同之處：名稱、外觀、生命值和傷害、移動速度和跳躍高度、
繪製的大小、穿著什麼、獵殺什麼又無視什麼，以及它是否仍遵守所根據
實體的生成規則。它是一個獨立的實體，有自己的生怪蛋和戰利品表，
被它所根據的那個實體則不受影響。村莊地塊可以被設定為安置它而不是村民。
它還可以帶有自己的儲存空間：物品欄位、流體槽和能量緩衝，管道和纜線都能
接入，玩家潛行並按右鍵即可開啟，Galacticraft 火箭也可以用同樣的
方式變化，並由 rocket 類型的物品放置到發射台上。

villages/<name>.json 檔案新增一個村莊可以建造的地塊，可以是你描述的
農場，也可以是你的 .nbt 範本之一。同樣的設定還能選擇哪些原版建築
仍會出現、村莊之間相隔多遠，以及它們允許出現在哪些生態域。

worldintro/<name>.json 檔案在有人進入世界時、取得控制權之前，播放
一連串頁面：圖片上捲動的文字、標題卡、投影片，需要的話還有背景音樂。
文字是 assets/<yourpack>/texts 底下的純文字 .txt 檔案。可以每位玩家播放
一次，也可以每次加入都播放。

teams/<name>.json 檔案在遊戲的計分板上設立一個陣營，生物、玩家或在
世界某個角落生成的任何東西到來時都會加入它，而 scoring/<name>.json
檔案則是一個把擊殺和死亡計給這些陣營的目標，依分數或時間結束一回合，
以聊天或卡片顯示排名，並能為下一回合重置地圖。

raids/<name>.json 檔案在帶著預兆效果的玩家走進村莊時，向村莊派出
一波波敵人。Boss 血條顯示還剩多少突襲者，村民會躲進屋裡，突襲者會砸
開木門，一波敵人到來時村裡的每口鐘都會敲響。

cards/<name>.json 檔案在發生某件事時（例如玩家進入某個生態域）
在螢幕上顯示一張卡片，同一資料夾裡以本模組自帶訊息命名的檔案，
可以改變那則訊息的內容。

整個世界
--------

資源包不限於單一事物。dimensions/<name>.json 登錄一個擁有自己的
地形、生態域和天空的維度。gates/<name>.json 為抵達維度設定
條件，例如持有或消耗某個物品。portal 類型的方塊會把走進去的人
送走，並記住是誰建造的。

世界範本還可以塑造主世界本身，設定海平面、熔岩海洋和地形雜訊。
它只在建立世界時套用，之後不再套用，所以已經存在的世界會維持原樣。

worldtemplates/<name>.json 把一個世界的設定收進一個檔案，
這樣資源包可以一次提供整個世界的形態，而不必要求
修改十幾處設定。它能設定的每一個群組，也都服從設定裡的 control 類別，
由它決定是資源包說了算、設定說了算，還是這個群組被徹底關閉、
任何資源包都無法開啟。

維度還可以設定它頭頂上的外觀和行為。它的霧、光照色調、太陽和月亮的
變暗、雲層以及熱浪都繪製在你自己的螢幕上，天氣則決定是否下雨、
下雪或雷暴、陣雨持續多久，以及雨的顏色、粒子、聲音和角度。

安裝了 Galacticraft 時，celestial/<name>.json 會把資源包自己的星系、
行星、衛星、小行星帶和太空站放到 Galacticraft 星圖上，帶有
galacticraft 區段的維度則成為火箭可以飛往的地方。

worldgen 不只是礦石。一個項目是由一種擴散方式放置的形狀：團塊、長礦脈、
板狀礦體、晶洞、碗狀地形、尖塔、結核、噴口、地表裝飾、整棵樹、
藤蔓、橫跨多個區塊的帶狀區域，或你自己的 .nbt 範本，可以均勻分布、
圍繞某個高度、以碎形分布、沿著地形、在洞穴地面或天花板上，或在水下。


biomes/<name>.json 檔案定義生態域：它的氣候和顏色、構成它的方塊、
裝飾它的東西、在其中生成的生物，以及它在哪裡生成。
它的編號由系統替你選定，並在每個世界第一次載入時寫入該世界，
所以無論你之後再安裝什麼，它都維持不變。只有當某個生態域必須
沿用別的東西已經用過的編號時才設定「id」，例如資源包取代一個
即將淘汰的模組。對世界裡已經存在的生態域重新命名或刪除，
會讓它遺失，和給方塊重新編號一樣，所以重新命名請改用 registry_remap。

村民顯示的名稱是語言鍵 entity.Villager.<career>，使用你所寫的職涯名稱，
一字不差。這個鍵的空間由 Minecraft 和所有其他資源包共用，所以請把你的
命名空間放進職涯名稱裡，如 rdpltest.prospector。受影響的只有名稱：
村民把職涯存成數字，所以重新命名會改變現有村民的稱呼，而調整職涯
清單的順序會改變他們的職涯。

藥水類型同樣以檔案命名，它顯示的名稱來自語言鍵
potion.effect.<namespace>.<name>，其他三種形態則用 splash_potion.effect.、
lingering_potion.effect. 和 tipped_arrow.effect.。


RUBIC 世界
----------

世界範本可以要求建造一個由立方體而不是 256 格方塊柱構成的世界，
這樣世界就會向兩個方向延伸：遠低於零的地板，遠高於 255 的天花板，
整個範圍裡都有地形、洞穴和礦石。在其中遊玩與平常無異。
你照樣挖掘、建造、照明和旅行，而原版的生成範圍在更高的世界裡
維持它慣常的形狀，所以生成地形的模組仍然落在它們一直以來的位置。

資源包能從中得到的：由它自己決定的世界高度，在建立世界時設定一次；
原版範圍之下的深層世界，帶有雜訊洞穴、含水層，以及在你指定的
石頭中的條帶狀礦脈；洞穴區域，也就是洞穴生態域在資源包中的對應做法，
在整個地下以三維方式繪製，帶有各自的地板、天花板、水位、生物和
結構；層疊在一起的維度，因此從一個世界的底部掉出去，會落進下一個
更深的世界，而從頂部爬出來則會回到上面；以及任何被省略的維度，
同一個存檔裡仍保留它原本的世界。

在底層，世界以 16×16×16 的立方體儲存，放在原版區域檔案旁邊的
專屬區域檔案裡，獨立地生成、載入和儲存，並配有專為這種形狀編寫的
光照引擎。原版「世界高 256 格」的假設，在凡是承重的地方都已打上修補，
從建造限制和虛空殺傷線，到尋路、傳送門、燈塔、地圖和轉譯器。
其他模組的生成器看到的仍是一個看起來正常的 256 格範圍，
這就是它們的地形能正常運作的原因。

HOWTO.md 裡有各項設定、世界可取的高度，以及這不能與之共存的模組。


關於 META 的警告
----------------

每個變體都有一個 meta 數字，世界檔案儲存的就是這個數字。
給人們世界裡已有的變體重新編號，會把他們的方塊變成別的東西。
新的變體請加在最後，永遠不要給舊的重新編號。

一個方塊有 16 個變體，因為四位元的中繼資料只能容納這麼多。
半磚有 8 個，因為一個位元用來表示在上還是在下，而樓梯、梯子、火把和
作物只有 1 個，因為朝向或生長階段占用了其餘的位元。
物品沒有這麼緊，可以跳過一些數字。


到此為止
--------

這裡描述的是事物是什麼，而不是它隨時間做什麼。任何需要
方塊實體、介面或每刻都執行的程式碼的東西，仍然需要真正的模組，
但有兩個例外：container 類型的方塊擁有帶自己介面的物品欄，
實體變體可以帶有儲存空間。機器是搆不到的；礦石、柵欄、食物
或流體則可以。


其他版本的資源包
----------------

為本模組 1.20.1、1.21.1 或 26.x 版本製作的資源包在這裡也能載入。
zip 會在自身內部被轉換一次，寫入 versions/1.12.2 資料夾，
現代版本的檔案保持原樣，所以同一個 zip 在每個版本上都能繼續使用。


查看你的變更
------------

按 F3+T 重新載入材質、模型、語言檔案、進度和戰利品表。在伺服器上，
輸入 /reload 也一樣。配方是例外，如上所述：它們只在啟動時載入，
所以修改配方需要重新啟動。

如果你新增或刪除了檔案，請改用 /rdpl reload。編輯一個
原本就存在的檔案，只需 F3+T。

/rdpl reload textures 只重新載入材質，在大型資源包裡比 F3+T 快得多。
models、languages、sounds 和 shaders 的用法相同。不寫名稱則重新掃描
資料夾並重新載入一切。

/rdpl list 顯示載入的每個資源包及其內容。點擊資源包即可查看。

/rdpl which minecraft:textures/blocks/stone.png 顯示是哪個資源包
提供了該檔案，以及它底下被遮蔽的資源包。

/rdpl config unused 列出 rdploader/config 裡不再被任何已安裝
資源包定義的選項檔案，/rdpl config prune 會刪除它們。
/rdpl pixelmap 顯示像素圖最終的樣子，/rdpl biome list 和 here
則告訴你生態域的資訊，/rdpl team 和 /rdpl round 用於資源包定義的
陣營和回合。

這些指令無需管理員權限，因為它們只讀取你自己電腦上的檔案。
在專用伺服器上，/rdplserver reload 會重新掃描伺服器的副本。


遇到問題時
----------

先看日誌。進度、戰利品表、配方、函式和結構都會連同它們來自的資源包
一起記入日誌，任何出錯的地方都會記為警告並說明原因。

對於材質和其他資源，/rdpl unused 會列出你的資源包中尚未被任何東西
請求過的檔案，這通常意味著路徑有拼寫錯誤。請在遊戲載入完成後執行，
並注意有些檔案只在需要時才會載入，例如你所用語言之外的其他語言。

大小寫很重要。如果你的檔案是 Stone.png 而遊戲請求的是
stone.png，它仍會載入，但警告會要你重新命名。請務必重新命名，
因為在這個模組之外，這個檔案根本找不到。
語言檔案最容易出錯：它們是 en_us.lang，不是 en_US.lang。

檢查你的檔案是否位於「assets」資料夾內。沒有它的 zip
會被略過，日誌裡會說明。



進度與配方
----------

如果你的腳本移除了某個配方，任何曾解鎖它的進度會繼續正常運作，
而不會損壞。只是它沒有配方可給你了，日誌會點名一次。

如果你用一個新配方取代了那個配方，並希望進度解鎖新配方，
請在腳本裡替新配方取個名字：

    recipes.addShaped("rail", <minecraft:rail> * 16, [[...]]);

這會把它登錄為 crafttweaker:rail。然後在這裡放一個指向該名稱的進度檔案，
進度就能重新完整運作。

沒有名字的話，它會被稱為類似 crafttweaker:ct_shaped-1834729103 的名稱，
那是配方本身的雜湊值。它在你一編輯配方時就會改變，而且如果在它之前
又新增了別的配方，它也可能位移，所以不能安全地讓進度指向它。


rdploader 資料夾本身可以用 config/mct_resourcedatapackloader_mixin.cfg 中的
rootDirectory 選項移動或重新命名。也可以使用絕對路徑，
需要重新啟動。

在這個檔案旁邊放一個 pack.png，可以為資源包設定圖示。

這個檔案由模組寫入，並在內容變更時更新，
所以你在裡面輸入的任何內容，在下次啟動遊戲時都會被取代。
